# 커밋·푸시 가드레일

이 스킬은 commit/push 행위를 사용자의 명시적 의사 없이 수행하지 않도록 막는 가드레일이다. 메시지 형식·언어 같은 표현 규칙은 프로젝트별 룰(`.claude/rules/commit.md` 등)에 맡기고, 이 스킬은 **언제 실행하는가**와 **무엇을 스테이징하는가**만 다룬다.

## 트리거

- 사용자가 commit/push를 요청하거나, 작업이 일단락되어 commit 의향을 물어야 하는 시점.
- 사용자가 "커밋·푸시할까요?"에 답하는 시점 — 응답 분류와 후속 동작 판단.

## 실행 시점

- `git commit`, `git push`는 사용자가 그 행위를 **명시적으로** 요청했을 때만 수행한다.
- 한 번의 승인은 **그 한 번**만 유효하다. 후속 작업의 커밋·푸시는 별도 승인을 받는다.
- 작업이 일단락되면 "커밋·푸시할까요?" 형태로 명시적으로 묻고 답을 기다린다.
- "커밋할까요?" 질문 직후 응답이 yes(또는 명백히 동등한 긍정)가 아니면 **모두 not-yes로 처리**한다 — 다른 코드 지시, 점검·재확인 요청, 질문, 무관한 메시지 모두 포함. 그 응답을 우선 수행한 뒤 작업이 다시 일단락되면 **다시 묻는다**.
- 직전 cycle이 "작성 → 묻고 → 커밋"으로 반복됐다는 이유로 다음 cycle의 승인을 추정하지 않는다. 매 cycle마다 새로운 명시 승인이 필요하다.
- "다음 단계로 진행해줘", "이어서 해줘", "이대로 가자" 같은 진행 지시는 **코드 작성·테스트까지만** 진행하라는 뜻이고 커밋 승인이 아니다.

## 스테이징

- 파일을 스테이징할 때 `git add -A` / `git add .` 대신 파일명을 개별 지정한다. 시크릿/임시 파일/대용량 바이너리가 우발적으로 포함되는 사고를 차단.
- 한 작업의 변경분과 무관한 다른 미커밋 파일이 작업 트리에 있어도 함께 스테이징하지 않는다.

## 프로젝트별 규칙

메시지 형식(언어·길이·스타일·금칙어)은 프로젝트가 정의한다. 이 스킬은 그 규칙을 대체하지 않으며, 프로젝트 룰이 있으면 그것을 따른다.
